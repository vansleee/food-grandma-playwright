## 相同條件與檢查

三個版本各自複製同一份初始資料庫狀態，再啟動 Playwright；使用相同餐廳帳號，建立相同名稱、描述、空圖片網址及價格 100 的餐點。一次使用一個 worker，失敗不重試。

三邊都先確認原有欄位，從網頁修改為 150，確認 HTTP 200 與回應中的原餐點編號及價格，再查詢編號清單、原餐點內容及同名餐點數量。最後重新開啟同一筆餐點，確認名稱、描述、圖片網址與新價格。

[comparison.json](comparison.json) 記錄三邊的實際資料與結果，逐欄比對相同；[summary.json](summary.json) 保存次數及結果。各版本的 evidence.json 另有 API 請求回應、狀態碼、主控台訊息及非 2xx 回應。

## 重現

依 chapters/README.md 完成專案內的 Python 與前端套件設定，再於 chapters/ 執行：

```bash
npm run chapter -- 15
```

指令會依序執行 no-pom、v1、v2，結果各放在本輪資料夾的 20/ 對應子資料夾。完整 trace、資料庫及私有密碼留在本機被 Git 忽略的 test-results/，路徑記錄於 summary.json。本次啟動的獨立服務已停止。

本實驗區各版本保存 results.json、stdout.log、launch.json、exit.json、evidence.json，以及載入原值、儲存後列表、重新開啟編輯頁面的三張截圖。密碼與 token 已遮蔽。

## 來源與取捨

未使用 POM 是從同一情境整理的教學版本。v1、v2 取自原始兩版的 POM 介面風格，統一帳號、API 資料準備與驗收要求，只保留本案例需要的方法；它們不是原始整套專案的逐字副本。原始 v1、v2 與書稿未修改。

三種寫法都能完成相同功能。v1 集中定位器，v2 為常用步驟命名，但也增加餐點列類別。這輪沒有模擬網頁改版，不能從三次通過推算長期維護時間。
