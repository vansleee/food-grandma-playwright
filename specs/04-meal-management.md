# 餐點新增、編輯與搜尋

## 目的與範圍

餐廳管理者可以新增、查看、編輯及搜尋所屬餐廳的餐點。頁面路徑為 `/management/meals`、`/management/meals/add`、`/management/meals/{id}/edit`。包含新增、查看、編輯與搜尋，不包含刪除、切換上架狀態或檔案上傳，也不檢查圖片網址是否能正常顯示圖片。

## 規則

- MEAL-01：餐點列表只顯示目前餐廳的餐點，包括名稱、描述與價格。
- MEAL-02：在表單中，名稱與價格必填；價格須為整數且不得小於 0。描述與圖片網址可留空。
- MEAL-03：新增成功後返回餐點管理頁，列表中可以找到新餐點；重新整理頁面後仍能看到。
- MEAL-04：開啟編輯頁時，表單先顯示該餐點的原有資料；儲存後更新同一個 ID 的餐點，不會新增另一筆。
- MEAL-05：搜尋文字只要出現在餐點名稱或描述中，就顯示該餐點，不區分英文大小寫。「沒有符合搜尋條件的餐點」與「尚未新增餐點」顯示不同提示。
- MEAL-06：儲存期間停用按鈕；失敗時留在表單，顯示「餐點儲存失敗，請稍後重試。」，保留已輸入的資料。
- MEAL-07：無法載入要編輯的餐點時，顯示「無法載入餐點，請重新整理頁面。」。透過 API 也不能查看或修改其他餐廳的餐點。

## 資料與前提

- 餐廳管理者已登入，進入所屬餐廳的餐點管理頁。
- 新增餐點時，需填寫餐點名稱與價格；描述與圖片網址可留空。
- 編輯餐點前，所屬餐廳已有該筆餐點，且編輯頁已顯示原有資料。
- 搜尋以所屬餐廳的餐點為範圍；沒有餐點時，顯示尚未新增餐點的提示。

## 驗收情境

| 測試案例 ID | 步驟 | 預期結果 | 對應規則／驗證方式 |
|---|---|---|---|
| MEAL-T01 | 新增餐點，填入名稱、描述與價格 120，圖片網址留空 | 返回列表，確認新餐點的 ID 與內容；重新整理頁面後仍能看到 | MEAL-02、03／UI 搭配真實後端 |
| MEAL-T02 | 開啟既有餐點，把價格改為 150 | 表單先顯示原有資料；儲存後同一個 ID 的餐點顯示新價格，沒有重複新增 | MEAL-04／UI 操作與 API 查詢 |
| MEAL-T03 | 名稱留空，或價格輸入負數、小數 | 瀏覽器的表單驗證不通過，不送出儲存請求 | MEAL-02／UI 資料驅動測試 |
| MEAL-T04 | 新增價格為 0 的餐點 | 可以儲存，透過 API 重新查詢後，價格仍為 0 | MEAL-02／UI |

| MEAL-T08 | 開啟編輯頁時，餐點資料載入失敗 | 顯示載入失敗的提示，不能當成正常的空白新增表單 | MEAL-07／模擬 API 回應的 UI 測試 |

## 限制與範圍外事項

### 功能限制

- 餐廳只能新增、查看、編輯及搜尋自己的餐點，不能操作其他餐廳的菜單。
- 新增與編輯時，名稱及價格必填；價格須為整數且不得小於 0。描述與圖片網址可留空。
- 每次編輯一筆既有餐點，儲存後更新該餐點，不新增另一筆。
- 只搜尋目前餐廳已載入的餐點，依名稱或描述中的部分文字比對，不區分英文大小寫；搜尋文字前後的空白也會列入比對。

### 範圍外事項

- 不包含餐點刪除、上架或下架，以及一次新增或編輯多筆餐點。
- 不包含圖片檔案上傳、圖片編輯，或檢查圖片網址是否能正常顯示圖片；本規格只包含圖片網址欄位的輸入與儲存。
- 不包含依價格搜尋、分類篩選、自行調整排序或搜尋其他餐廳的餐點。
