# 外送員接單權限規格（AI 產生草稿）

狀態：AI 根據 `specs-draft/01-restaurant-auth/` 輸入資料整理；待人工審查，尚未核准或執行測試。不可直接視為正式測試判準。

## 目的與範圍

整理外送員接取待取餐訂單的預期行為，聚焦進行中配送數量上限、接單結果及畫面更新。本草稿只處理外送員接單，不涵蓋顧客、店家管理者或跨角色權限矩陣。

## 角色與前提

- **角色**：外送員。
- **目標操作**：從「可接訂單」頁接取一筆狀態為待取餐、尚未指派的訂單。
- **進行中配送**：此草稿依輸入資料以外送員目前配送中的訂單數量判定；具體後端狀態範圍仍需查核。
- **測試資料**：至少準備一筆可接訂單，以及外送員目前進行中配送數量可控制的資料。

## 業務規則

- ROLE-01：外送員目前進行中配送少於 3 筆時，可以接取一筆符合條件的訂單。接單成功後，訂單應指派給該外送員，進入配送中，並即時出現在「進行中配送」頁。
- ROLE-02：外送員已有 3 筆進行中配送時，不得再接取第四筆訂單；接單被拒後，既有配送及新訂單的狀態與指派資料均維持不變。

## 測試資料與技術線索

- 接單 API 候選為 `POST /api/driver/orders/{order_id}/claim`，請在產生 API 測試前查核目前程式與 API 契約。
- 接單請求的認證傳遞方式及失敗回應尚未重新查核，不在此草稿中推定 HTTP 狀態碼或回應格式。
- 測試資料需能建立外送員分別有 2 筆與 3 筆進行中配送的情境，並能識別待接訂單及其指派狀態；具體 seed／fixture 能力待查核。
- UI 路徑與可見文字須在實際網站確認；畫面觀察不能取代資料持久化驗證。
